# 开发说明：实验组、检测结果与证据边界

[README](../README.md) 说明首次使用与汇报。本文件解释目录的实现、现有 Fisetin 案例的纠错方式，以及未来扩展时必须保留的科学边界。包名 `chem-pdf-extractor`、版本 `0.4.0`、虚拟环境 `SenoMiner_AI` 与 Python `3.11.15` 保持不变。

## 1. 数据流和文件

`启动项目.command` → `run_senolytics.py`（检查虚拟环境并读取 `.env`）→ `entrypoint.py` / `app.py` → `server.py`。服务只绑定 `127.0.0.1`。`/catalog` 是统一页面，包含论文输入、提取进展、化合物列表和详情。旧的 `/` 与 `/showcase` 链接重定向到 `/catalog`，不再提供独立工作台或原始候选展示。原始记录相关网页、接口、演示启动逻辑及旧页面模板已删除；本地原始报告不删除。

`biomedical.extract_article` 调用 `sources.load_paper` 获取 PMC 全文或使用 `pdf.py` 解析本地 PDF，保存 `source.md`，按 8,000 字符和 1,200 字符重叠提取。`biology.py` 定义的规则和字段发给模型；`validation.py` 对关键字段和步骤的逐字引文查原文位置。随后 `claim_review.py` 做全文角色/药效方向复核，`evidence_cards.py` 为通过名称重新从全文关联效果句与支持实验，避免沿用混合的原始记录。`enrichment.py` 通过 `vendor/science-skills` 的 PubChem、ChEMBL、PubMed 脚本补充分子身份。原始输出为 `report.json`、`source.md`、`experiments.jsonl`、`experiments.xlsx`；独立派生文件为 `claim_review.json` 和 `evidence_cards.json`。

模型按**检测结果**保存原始候选，因此 `report.json` 的记录数不等于独立实验数。`experiment_id` 根据来源及模型、剂量、时间、检测与结果生成，可去除完全相同的记录，但不能识别 Methods、Results、图注和 Discussion 对同一实验的不同表述。网页目录使用单独的分组层，不篡改可追溯的原始报告。

## 2. 两层身份：实验组与检测结果

**独立实验组**以同一论文内的对象或队列、干预、对照、剂量/途径/时间窗为单位。**检测结果**是该实验组下各个终点、方法、样本量、统计结果和原文引文。同一动物队列的寿命、ALT、淀粉酶与病理评分可在一个组中作为不同结果；不同基因型的两批小鼠即使用同一剂量，也不得直接归为同一队列。临床受试者服药后取组织活检属于人体给药研究；手术取组织后在培养皿加药属于 `ex_vivo`，不能标为人体临床给药。

当前网页的实验组来自 `evidence_cards.py`，每张卡按设计/队列组织并保留参数原文，身份键含造模原文、图、对象原文和处理条件。相同设计的不同结果合并，不能仅凭细胞名和剂量就把自然衰老与照射造模混为一组。`experiment_groups.py` 保留剂量/结果分类等辅助以及旧记录分组的离线比较代码，旧分组输出已不作为目录数据。审查时需要遵守以下边界：

- PMID 31542391：D+Q 三日人体给药、同一受试者队列；Fig. 1 与 Fig. 2 的指标合并成一个组，再把 p16、p21、SA-β-gal、CD68 巨噬细胞与冠状结构的重复表述合为五种检测结果。活检组织是检测材料，不能因此把给药研究改成 `ex_vivo`。
- PMID 30279143：Fig. 1 的 MEF 筛选、MEF 浓度响应和 IMR90 浓度响应分开；Fig. 2 间歇性饲料给药、Fig. 3 长期饲料给药分开；Fig. 4 的老年 WT 小鼠、INK-ATTAC 小鼠与人脂肪组织离体处理分开；Fig. 5 的晚年起始长期给药是一组，含寿命、血液生化、病理、组织基因表达、循环 MCP-1 和肝氧化应激等七类终点。
- PMID 26657143：ABT263 的 Fig. 1 细胞筛选、Fig. 1 照射小鼠、Fig. 2 细胞凋亡、Fig. 3 照射小鼠 HSC 与 Fig. 4 自然老年小鼠分别成组；同一照射队列的 Supplementary Fig. 9 归回 Fig. 3。ABT199 + WEHI539 仅作为原文明确试验的组合，不能拆成两个单药效果。GCV 依赖 p16-3MR/HSV-TK 转基因，是清除细胞的实验对照，不作为通用抗衰老候选药物。

这些是核对队列时的边界要求，不能据此宣称自动提取已完整覆盖每个实验。生成的卡仍可能遗漏设计或关联错误；如果未来有人工标注集，才可评价实验组 precision/recall。不能用当前页面数量宣称准确率。

## 3. 什么进入目录

`catalog.py` 逐篇读原始报告、全文和同源派生文件。名称先须在 `claim_review.json` 通过全文复核：作用方向为 `beneficial_against_aging`、角色为 `active_intervention`、范围为 `senolytic/senomorphic/lifespan/aging_function`，且有支持实验。随后必须在 `evidence_cards.json` 中取得可定位的原文效果句、结果、对象和检测方法，才能进入目录。第一遍的 `positive` 仅是待复核输入，不能证明药物有效。

`claim_review.py` 为每篇论文额外发起一次当前配置模型的完整原文审阅，要求返回：药物角色、作用方向、明确组分名、是否依赖工程化自杀基因、作用范围、原文效果句，以及每条被接受实验的 ID 和连续结果句。全文超过 450,000 字符时拒绝静默截断，转人工处理。网络/结构错误、缺失决定、无法定位的引文及未知实验 ID 均不会放行；失败可以重试。多个同名决定按明确实验 ID 合并，只有一致的分子身份可合并，方法记录不会因同药其他实验有效而一起放行。复核不是科学真实性认证，同模型仍可能重复第一遍的偏差。

复核副本保存 `policy_version`、全文 SHA-256 及关键候选字段指纹。原文或关键字段改变时，旧决定失效；数据库属性的补充不会使原有决定失效。模型原始复核输出保存在该论文的 `review_responses/`，允许追查模型判断与后处理规则。原始提取报告保持不变。

这次用六篇真实报告检查了两种误判：5-FU 被错误标为积极结果，但其作用是增加衰老表型，属于造模；abemaciclib/LLOMe 的癌细胞序贯治疗不构成一个独立抗衰老化合物。Piceatannol 与真正共同起效的组合则保留其明确的模型边界。另将转基因自杀系统中的清除药排为遗传消融对照，不当成常规药效。

Chang 2016 的实际运行发现部分模型响应把引文键写为字段编号（例如 `field_19` 对应 `observed_result`）。`validation.py` 与 `catalog.py` 同时支持字段名及已知编号，但依旧需要逐字匹配原文。原始 `report.json` 不改写；修复后的 `report.revalidated.json` 标明 `derived_from` 和相同的 `source_sha256`，目录只有在来源信息一致时才读取这个复核副本。四段式摘要由 `evidence_story.py` 从通过过滤和归组的数据生成；对展示的人工整理句，仍先检查对应原文锚点。Piceatannol（DOI 10.3390/ijms26189134）的简短阅读步骤同时要求原文包含 5FU 造模、24 小时恢复、PCT 处理、Annexin V、SA-β-gal、CCK8 和非衰老细胞对照等锚点，且当前主实验必须是对应细胞实验；缺失时使用原始已核验参数，不借用该摘要。此层只改变展示，不修改提取记录、药物角色判断或收录条件。

`evidence_cards.py` 接收通过角色复核的名称和完整原文，重新抽取设计与多个子结果；不把旧记录的 ID 与一个不相关的新引文强行拼在一起。效果句和结果必须在原文连续出现；`result_location()` 尽量用实际章节覆盖模型的错误位置标签，摘要/讨论/参考文献中的句子不能冒充 Results。原文标题格式损坏时采用保守的 Results/图注提示，仍可能需人工核对。

对象、剂量、时间、给药、样本量、对照、检测都有单独原文引文。数值字段若不原样出现在引文中就清空；对象和检测的模型概述若不逐字匹配，则丢弃概述，只显示完整可定位的相关原文描述。无法定位对象或检测的卡不展示。格式错误的参数最多另做一次修复，修复后继续严格匹配，并保留原输出及修复响应。卡与当前全文/候选指纹及通过名称绑定；空卡或不合格卡不会退回原始混合记录。

`field_evidence`、`procedure_steps` 和 `evidence_checks` 仍供审查。字面匹配只证明句子存在，不能独立证明实验关联正确，因此仍需核对模型提取的设计边界。步骤只采用找到原文引文的动作句；缺步骤时页面提示查阅 Methods/补充材料。

## 4. 剂量与效应的科学解释

`model_type` 采用 `in_vitro`（细胞）、`ex_vivo`（离体组织）、`in_vivo`（动物体内）、`clinical`（人体给药）。`dose_details()` 识别剂量分母：`500 ppm (500 mg/kg)` 是 **每千克饲料含 500 mg**，并非每天每千克小鼠体重给予 500 mg；`100 mg/kg` 加 `oral gavage` 是每千克体重口服灌胃。Figure 2 论文另估算实际摄入约 60 mg/kg/day，也不改变饲料配方的单位含义。

`outcome_kind()` 把检测结果标为寿命、炎症/SASP、器官功能/病理、衰老标志物或细胞死亡/凋亡。标志物下降、SA-β-gal 阳性比例下降不能自动推断细胞被杀死；Fisetin 原文也指出在 MEF 中未见明确细胞杀伤证据。只有直接细胞死亡或凋亡实验才能作为清除证据。此分类是显示提示，不能替代逐条人工判读。

## 5. 3D 分子图和数据库边界

化合物名称先由全文复核确定原文的实际活性实体，再由 `enrichment.py` 确认唯一 PubChem CID。原文定义的 `Piceatannol (PCT)` 展开后查询 Piceatannol，避免把局部简称直接送到数据库。唯一 CID / 完整组分 CID 用于别名聚合，不将联合结果拆成单药。无法可靠确认的身份不会凭名称猜成其他分子。

`/api/catalog/structure?cid=` 只接受数字 CID，调用 `structures.py` 优先取 PubChem 3D SDF。没有 3D 时读取同一 CID 的 PubChem 2D 化学结构，由 `RDKit 2026.9.1` 的 ETKDGv3、固定随机种子、单线程及超时参数生成构象，尽可能进行 MMFF/UFF 优化。生成前后比较去氢后的异构 SMILES，拒绝分子图或立体化学被改变的结果。结果必须有可解析的原子、三维构象与有限坐标。

结构及来源标签缓存于 `output/.structure_cache/<CID>.sdf` 和同名 JSON；来源标签绑定 SDF 内容 SHA-256。API 的 `origin=pubchem_3d` 表示 PubChem 构象，`origin=rdkit_etkdg` 表示本地计算构象，列表分子预览下逐一标注。已实际验证 ABT263 / ABT199 的 PubChem 3D 缺失可走 RDKit 备用路线，Fisetin 则直接使用 PubChem 3D。联合用药逐个成分显示。没有确认 CID 或两条路线均失败时仍显示原因，不展示其他分子的图。

列表原“主要发现”列改为 `catalog.js` 的 Canvas 3D 投影，支持拖动旋转，不依赖 WebGL。尺寸按容器及分子半径适配；预览静止时不持续重绘，切页会清理监听器和尺寸观察器。结构请求按 CID 在浏览器中共享，5 秒数据刷新不重建未变化的列表。详情最上方直接显示“分子结构与数据库信息”，打开详情即加载分子图，随后展示“原文依据、实验步骤、实验结果、结论”，不再显示“有本篇实验支持”等重复标签；更多实验和参数默认折叠。详情查看器保持默认展开，可切换本地 `3Dmol.js`。PubChem 提供化学信息，PubMed 提供论文；这些外部信息不替本篇论文补疗效。计算构象仅供视觉识别，不是实验结构、对接有效性或药效证据。

目录按 `read_at` 倒序；旧报告采用原始报告的完成时间。化合物按其最新来源文献的读取时间排序，复核副本或缓存修改不影响顺序。新报告保存明确的读取时间；不会用论文发表年份或名称字母顺序替代。页面默认每页 5 项，可选 5/10/20，支持前后页及页码跳转，筛选后回第一页；来源列显示完整论文名。

## 6. API、安全与维护

| 路径 | 用途 |
| --- | --- |
| `GET /catalog` | 简洁的跨文献目录页 |
| `GET /api/catalog` | 化合物、来源论文、实验组与终点 |
| `GET /api/catalog/search?q=` | PubMed 候选研究检索 |
| `POST /api/catalog/import` | PMID 公开全文后台提取 |
| `POST /api/catalog/upload-pdf?name=` | 校验文件名、大小和 PDF 文件头后保存 |
| `POST /api/catalog/process-pdf` | 后台提取已上传 PDF |
| `GET /api/catalog/structure?cid=` | PubChem / RDKit 3D 结构、来源标签与本地缓存 |

受保护 API 需要回环地址、页面 token 和 Origin/Referer 检查；前端展示内容做 HTML 转义。`pyproject.toml` 将目录 HTML、CSS、JS 和 3Dmol 静态文件纳入包。`.env`、论文、生成报告、缓存与虚拟环境不提交 Git。当前云端模型是 `doubao-seed-evolving`；更换模型后必须重新验证结构化输出并重新提取，不应混算不同模型的记录。

```bash
.conda/SenoMiner_AI/bin/python -m pip check
.conda/SenoMiner_AI/bin/python -m unittest discover -s tests -v
.conda/SenoMiner_AI/bin/python -m chem_pdf_extractor --help
.conda/SenoMiner_AI/bin/python -m chem_pdf_extractor.biomedical --help
git diff --check
```

## 提取任务的进展与恢复

`catalog_progress.py` 为当前单任务维护线程安全状态：`source`、`kind`、`status`、`stage`、实际完成的 `completed/total`、开始/更新时间、结束时间和最近 30 条运行记录。`GET /api/catalog` 同时返回此 `task`；完成或失败后耗时固定，运行中前端每秒更新耗时、每 3 秒读取服务状态。分段任务并行结束后才增加完成数，缓存复用也算一个已完成分段；下一阶段清空分段计数，避免把提取完成误当整个流程完成。

上传按钮现在连续执行上传与提取；开始接口立即返回任务信息，页面不等待首次定时刷新才显示运行状态。PDF、编号导入和重试共用右侧状态区；已完成文件仅在折叠列表中出现。失败的全文核对/实验关联即使已有 `report.json` 也不跳过，重新进入流程时复用成功分段和已通过的同源复核缓存。

`POST /api/catalog/import` 支持 `{"identifier":"DOI:10.x/y"}`、PMID、PMC 编号，并兼容旧的 `{"pmid":"123"}`。`sources.py` 统一验证标识，禁止任意 URL / 本地路径；DOI 使用精确 `[AID]` 检索，避免附加抗衰老关键词导致漏掉指定论文。随后沿用 PubMed → PMC 全文路径；只有摘要时以 `needs_pdf` 结束，不调用提取模型。编号导入的模型、提取、复核与数据库流程和 PDF 相同。

`network.py` 在标准 HTTPS 上下文中加载当前环境的 certifi CA，解决项目重命名后 Conda 的编译时 CA 路径过期；第三方 Science Skills 子进程在没有显式 CA 配置时获得相同 CA 路径。仍强制证书与主机名校验。证书错误单独报告、不按瞬时网络故障重试；普通网络故障有限重试且不递归拆分原文，只有响应结构不完整时才拆分。密钥和上游敏感诊断仍执行脱敏。


## 统一展示入口

页面只保留论文输入、提取进展、化合物列表和解读详情。取消旧批量 PDF 配置面板、自定义字段模板、模型配置卡片及原始候选记录表；模型配置继续读取本地 `.env`，后台批量与 CLI 功能保留。旧页面的布局、自动滚动和模型下拉框测试随被删除的界面一起退役，改用统一页面路由、原始记录接口不可访问、分子信息置顶与自动加载的验证；云端配置安全、任务恢复、导出和提取本身的测试继续执行。
